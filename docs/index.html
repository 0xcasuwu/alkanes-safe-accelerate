Proof of concept · runs on your computer

Speed up a stuck alkanes transaction, safely

A wallet's own "Speed up" rebuilds your transaction, and that can send alkanes, runes or inscriptions to the wrong place or burn them. This accelerator only raises the fee. Every input, output and data field stays exactly as it was, and it checks that before anything is signed.

1 · Before you start

  • A Mac or Linux computer (on Windows, use WSL).
  • Node.js 18 or newer. Check with node -v in Terminal. If it's missing, install it from nodejs.org, or with Homebrew: brew install node.
  • git, which most Macs already have (if not, Terminal will offer to install it).
  • No GitHub account: the code is public at github.com/0xcasuwu/alkanes-safe-accelerate.
  • A small test wallet and its recovery phrase, and the stuck transaction's id.

2 · Start it: one command

Open Terminal, paste this, and press Return:

[ -d ~/alkanes-safe-accelerate ] || git clone https://github.com/0xcasuwu/alkanes-safe-accelerate.git ~/alkanes-safe-accelerate && bash ~/alkanes-safe-accelerate/accelerate.sh

The same command works every time, first run or fiftieth.

What it does

  1. Downloads the accelerator to a folder in your home folder, alkanes-safe-accelerate, the first time only. Later runs reuse that folder and pick up any updates.
  2. Checks every file of the app against the fingerprints recorded when it was built, and refuses to start if anything differs.
  3. Starts a small server on your computer only (nothing on your network can reach it). It passes the page's blockchain lookups to SUBFROST, the way the SUBFROST app's own server does.
  4. Opens http://localhost:4173 in your browser. If that port is busy it picks the next free one, and Terminal shows the address.

Keep the Terminal window open while you use it. To stop, press Ctrl+C in that window, or close it.

Want to read the script before running it? accelerate.sh is short and commented. Nothing is installed: it needs only git and Node, and you remove it by deleting the alkanes-safe-accelerate folder.

3 · Use it

  1. Unlock. Paste the test wallet's recovery phrase. It stays in that browser tab's memory: it isn't saved anywhere or sent anywhere, not even to the server in your Terminal, and it's gone when you close or reload the tab.
  2. Check the address the page shows is your wallet's. (It uses the standard paths: taproot bc1p… and native segwit bc1q….)
  3. Paste the stuck transaction's id and press Check. The page reads the transaction and says whether it can be sped up safely, or exactly why not.
  4. Pick a fee rate. The plan shows the new fee and the one thing that changes: your own BTC change, lowered to pay it.
  5. Press "Check: sign and verify, don't broadcast" first. It signs and runs every check, including asking a Bitcoin node whether it would accept the result, then stops. If that passes, "Accelerate: sign and broadcast" sends it.

Never use your wallet's own "Speed up" on an alkanes transaction, before or after using this.

What it protects, and what it can't

AssetProtection
AlkanesThe replacement is the original byte for byte except one amount: your change. Alkanes are routed by position, not amount. Before signing, the page also asks SUBFROST's indexer to settle the original and the replacement side by side, and refuses if any output's alkanes differ.
RunesEvery output and the data field are unchanged, and runes are also routed by position.
InscriptionsNo inscribed sat may change outputs or be spent as fee. If the inscription index can't be read, it refuses.
Your BTCOnly your own change goes down, never below 546 sats, within fee caps, checked again on the signed transaction.
Rare sats, AtomicalsNot protected: nothing SUBFROST runs indexes them. The plan lists which sats move into the fee. Move valuable ones out first.
Contracts tied to the transaction idPartly: unknown data and payments to script addresses are refused unless you confirm it's a plain payment, and SUBFROST peg-outs are refused. A wrong confirmation can't be caught.

Whenever data can't be read or something changes between steps, it stops instead of guessing. It can't detect a data source that is confidently wrong. The safety checks are tested one by one (each removed alone turns a test red), on devnet, and on mainnet: the replacement of a real alkanes transaction waiting in the mempool settled its alkanes identically and passed the acceptance test of two independent Bitcoin nodes. This is a proof of concept and the code has not had an outside review.

Not in this version

  • Adding a separate coin to pay the fee. The fee comes out of the transaction's own BTC change, so a transaction whose change is too small is refused. The SUBFROST app version can add a coin.
  • The app's records of in-flight packages and peg-outs.
  • Browser wallet extensions (Xverse, Unisat, …): recovery phrase only, for now.

If something goes wrong

"Node.js is not installed" or "too old"
Install version 18 or newer from nodejs.org, then run the command again.
"Download failed", or git says "Repository not found"
Check your internet connection. If it persists, the command changed while copying: copy it again with the Copy button.
"No such file or directory" naming accelerate.sh, or "already exists and is not a copy"
A different folder named alkanes-safe-accelerate is in your home folder. Rename it and run the command again.
"does not match the build"
A file in the download was changed or damaged. Delete the alkanes-safe-accelerate folder and run the command again.
The browser didn't open
Open the address shown in Terminal, usually http://localhost:4173.
The address shown isn't my wallet's
Try another account index. Wallets using other address types (for example 3… nested segwit) aren't supported yet.
Refused: not this wallet's transaction
The transaction must be one the unlocked wallet signed.
Refused: change too small, or no change
There's no BTC change big enough to pay the extra fee. See "Not in this version" above.
