How it stays safe

An alkanes transaction moves tokens by output position: the OP_RETURN's protostones name outputs by index, and every input's balance is routed through them. Change the number or order of outputs and the same protostones point somewhere else.

  • Clone, never rebuild. The replacement is the original byte for byte (version, lock time, every input, sequence and script, the OP_RETURN) except one value: your last output of real value goes down by the extra fee.
  • Or add one clean coin when that change cannot pay: a coin proven free of alkanes, runes and inscriptions, with ≥ 3 confirmations. (The app does this; this read-only page cannot prove a coin alkane-free, so it stops.)
  • Refuse instead of guessing: if anything spends one of its outputs, if it calls a contract that follows it by txid (frUSD and frFB peg-outs and redeems), if the sats moving into the fee might be inscribed, or if any fact is unreadable.
  • Never break what waits on the txid. A replacement has a new transaction id. It is refused when the transaction carries another protocol's data (Counterparty, Omni, Babylon, RGB, Stamps), and when it has no runestone and pays a script address (the shape of an inscription or rune commit, a staking deposit, a Lightning channel) unless you state it is a plain payment. A coin is never added to a payment to someone's taproot address (a silent-payment recipient would lose track of it).
  • Settle exactly like the original. In the app, the indexer runs both the original and the replacement; every output must end with the same alkanes, so a contract that reads the transaction itself cannot behave differently.
  • Verify the signed bytes. In the app, the wallet's answer is checked to be the planned transaction plus signatures only, signed SIGHASH_ALL, paying the planned fee on its real size, before anything is broadcast.

What this page cannot do

Sign, broadcast, add a fee coin, run the app's alkane-conservation gate or its original-versus-replacement simulation, or read its records of in-flight packages and peg-outs (those need SUBFROST's indexer and your app session). Rare sats and Atomicals are not indexed anywhere SUBFROST reads: the plan says which sats move into the fee. To act on a plan, run the accelerator on your computer (setup guide) or use Accelerate in the app.

Proof

  • Engine (subfrost-wallet-common accelerate): 49 unit tests, including a red case per guard, a field-by-field attack on the verifier, a replay of Xverse's append, and a 400-case property test against the indexer's own routing model.
  • Mutation proof: each of the 37 guards, disabled alone, turns a test red.
  • Mainnet differential (read-only): replacements built this way, simulated by mainnet's indexer at the original's block, routed alkanes identically on 33 of 33 recent alkanes transactions; the Xverse-style replacement changed routing on 15 of 33 (one sent an LP position to an output nothing spends).
  • App: end-to-end tests against the real engine with real signatures; every race between planning and signing refused before broadcast.
